# gem-review-app

The shared review app behind the GEM researcher repos. A reviewer opens a page of staged edits (a plant or a pipeline per card; GOGPT also gives a plant separate cards for its proposed additions and its watch list), accepts, holds, rejects or suggests each one, calls the items that are not cell edits, and the decisions land in that repo's decision log. The page, the store adapters, the decision log and the loopback server live here once; each tracker adds its own config and page extension under `trackers/<name>/`; each researcher repo keeps only its dataset builder, its Google ledger and its workbook consumers, and imports the rest from this sibling checkout (`../gem-review-app`, or `$GEM_REVIEW_APP`).

Start with `docs/plan.md`: what lives where, the dataset contract, the tracker config, the page hook points, the store interface and the single-file page format. `docs/refresh.md` is the plan for keeping every published page current (page registry, staleness check, hooks); built and in use, the hooks carry it. `docs/audit_pipelines_2026-10-22.md` is the open UX, UI and design audit of the pipelines page: a checklist of findings with code anchors, worked top to bottom. `docs/audit_lng_2026-11-05.md` is the same kind of list for the LNG carriers page, read against the GOGPT and pipelines pages.

Consumers today: `gogpt-researcher/review_app` (phase one), `pipelines-researcher/review_app` (phase two, landed 2026-10-09) and `lng-carriers-researcher/review_app` (phase three, built 2026-10-29 on the `baird` branch).

One look across trackers: a change to how a card shows something (link check marks, new-row layout, chips) lands on every tracker page that has the same thing, GOGPT, pipelines and LNG carriers alike, not just the one it was asked for. Shared drawing goes in `review_core/web/app.js` (for example `sourcesTable`, the sources block under a new row's data points (on GOGPT one per plant or unit), and `vmark`, the link check mark) and each tracker maps its own data onto it; only tracker-specific content, like GOGPT's engine-capacity grouping, stays in one extension.

Tests: `python -m pytest tests -q` here runs the core on a synthetic tracker; each researcher repo's own review tests exercise its port.
